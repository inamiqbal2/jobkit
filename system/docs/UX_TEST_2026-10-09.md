# v0.2 UX test - a fresh clone driven the way a non-technical user's Claude session would drive it (2026-10-09)

Method: `git clone` of the repo to a scratch folder with no `.venv`, then every step was done the way `CLAUDE.md` and the three
skills tell Claude to do it, with the fabricated Marina profile (`system/examples/marina_example`) supplying the "answers". Network on;
Adzuna off; USAJobs idle (no key); Indeed on (python-jobspy installed by setup.py because the workspace asks for it).

## 1. "set me up" -> phase 0 (setup.py on a bare clone)
`python3 system/engine/tools/setup.py` took 17 s (warm pip cache; 1-5 min cold). User-visible outcome, as Claude would phrase it:
> "Your computer is ready: Python 3.13, the tool's own environment is installed, LibreOffice and poppler are present so I can
> check page counts. Nothing about you is filled in yet; that is what the interview does next."
Status table printed: Python ok, .venv created, packages installed, 13 workspace files created from templates (settings.yaml still
the placeholder person), ledger database created, job-board packs none selected yet, USAJobs key not set, onboarding 1/21.
Running it again (`--quick`) changed nothing and said so ("all present (nothing overwritten)").

## 2. Phases 1-3 simulated (welcome, identity, work authorization)
The questions Claude asks (one per message, examples in each) and Marina's answers were taken from the example; Claude's writes:
`settings.yaml identity` + `work_authorization`, and the status rows 1-3 -> done. The read-backs the user sees:
> "Your contact line will read: 808-555-0162 | marina.example@example.com | linkedin.com/in/marina-example | orcid.org/... |
> Kaneohe, HI. Correct?"
> "On your CV: 'U.S. Citizen'. I will drop nothing for citizenship, clearance or export control; I will keep everything else. Correct?"
**Resume check**: a new session's `setup.py --quick` reported "4/21 phases done; next: 4 location, commuting, relocation", and
`userconfig.py` read the name. Resuming works from the status file alone.

## 3. "run my job search" on the marina workspace (daily skill, steps 1-7)
- Step 1 quick check: assembled the active job-board lists (first run on a clone has none), installed python-jobspy (asked for in
  settings.yaml), reported "20/21 phases done; next: 16 USAJobs key" (optional; the gate is phase 18, which is done).
- Step 2 `daily.py`: 1,985 candidates from 15 keyword boards + LinkedIn + Indeed + the watch list -> 26 geography drops ->
  1,979 screened -> 26 passed the title-blind gate -> queue + rubric batch. Exit 0, ~25 minutes, no traceback. USAJobs and Adzuna
  each printed one "off" line.
- Step 3: two blind judges (Fable subagents, prompt file only) wrote run_A / run_B; `rubric.py merge` averaged them, auto-set
  aside 2 clear rejects, kept 24 for judgment (rubric order 83, 66, 56, 49, 42, ... 1).
- Step 4: all 24 judged per the charter thresholds and ledgered with `decide.py` (3 BUILT, 2 WATCH, 19 SKIP, each with a reason).
- Step 5: three academic CVs built from approved claims only (critic CLEAR, entry scorer ERI+THESIS+KEYS, 2 pages, audit PASS,
  consistency PASS, keyword pass: one honest gap "divemaster", one ASK term "project management").
- Step 7: `reports/2026-10-09.md` written and shown (copied into `system/examples/marina_example/reports/`). Its first lines to the user:
> "I checked 15 keyword job boards, the university and agency HR systems in your pack, LinkedIn and Indeed listings, and your
> watch list. 1,985 postings were seen; ... 26 passed the fit gate and were scored by two independent judges. Federal postings
> are idle until your USAJobs key is set. Nothing was applied to."

## What would have confused or blocked a user, and what was changed
| found | fix (committed) |
|---|---|
| A fresh clone has no active registry files; the first `daily.py` would have failed | `setup.py` assembles them from the selected packs when missing (and takes the first watch snapshot) |
| `--quick` left a requested optional package uninstalled, so the Indeed arm would silently skip | `--quick` installs a missing package the workspace asks for |
| The examples' status files were in the old 15-step format; the progress parser and the daily skill's "setup finished?" gate misread them | both rewritten in the 21-phase format |
| The critic flagged 9 of 26 queue items "BELOW LEVEL: technician/HS tier" for a person whose target IS technician roles | `settings.yaml targets.hourly_ok` (critic switch; onboarding phase 5 asks it; marina sets it) |
| The job-card header (SOURCE / APPLY / FIT) was counted as JD keywords ("posted", "apply", "waf" listed as missing) | `verify_resume.py` and `keywords.py` ignore the header above the `==========` rule |
| LibreOffice installed as an app but not on PATH would skip the page check silently | `verify_resume.py` also tries the .app / Program Files locations; `setup.py` reports the same |
| `registries.py list` legend line was parsed as a pack name in the status table | fixed |
| The LinkedIn/Indeed-sourced builds need the employer's own link; UMass Dartmouth's PageUp site answers automation with a WAF challenge | the skill's fallback applied: the card names the employer's careers site and says the posting page must be opened in a browser; NV5's iCIMS posting was found through the portal's iframe endpoint |

## What still requires the user to touch a terminal or a file
Nothing. The one website step is the USAJobs key (two minutes on developer.usajobs.gov; pasted into chat). Installing Python
itself, if a computer lacks it, is proposed by Claude and done after a yes (Homebrew on macOS or the python.org installer).

## Known limits seen in this run
- The priority-lane patterns of the marina example are loose (`anchor: marine` etc.), so 20 of 26 queue items carried the
  "never auto-skip" mark and had to be judged by hand; a real user's phase 17/18 tightens them. Judgment still took one pass.
- Employer sites behind WAF / client-rendered portals (PageUp, some iCIMS) cannot be read by `curl`; the card falls back to the
  employer's careers page, as the constitution prescribes.
